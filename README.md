# pyファイルをまとめてテキスト化(GPT確認用) ReadMe

## 概要
「pyファイルをまとめてテキスト化(GPT確認用)」は、ディレクトリ直下にあるPythonスクリプト（.pyファイル）を読み込み、その内容を1つのテキストファイルにまとめるユーティリティです。このツールは、特にプログラムの内容を一括して確認したい場合や、ドキュメント化の作業を行いたい場合に便利です。

- 対象は指定ディレクトリ直下の`.py`ファイルだけです。サブディレクトリの中は読み込みません。
- 各ファイルの内容は「```ファイル名」と「```」で囲まれ、ファイル名順に連結されます。
- 連結された内容は`Pythonファイル内容全文.txt`という名前のファイル（UTF-8）に保存されます。

## 使用方法
Pythonスクリプト（`main.py`）と、Windows用の実行ファイル（`.exe`）の2通りがあります。

### Pythonスクリプトで実行する
Python 3.10以上が必要です。標準ライブラリだけで動作し、追加のインストールは不要です。

```
python main.py
```

引数なしで実行すると、カレントディレクトリ直下の`.py`ファイルをまとめ、同じディレクトリに`Pythonファイル内容全文.txt`を保存します。macOSやLinuxでは`python3 main.py`としてください。

| 引数 | 内容 |
|---|---|
| `directory` | 対象ディレクトリ。省略時はカレントディレクトリ |
| `-o`, `--output` | 出力ファイル。省略時は対象ディレクトリの`Pythonファイル内容全文.txt` |
| `--fallback-encoding` | UTF-8でもエンコーディング宣言でも読めないファイルに使う文字コード（例: `cp932`） |

```
python main.py C:\work\project -o C:\work\project.txt
python main.py --fallback-encoding cp932
```

### Windows用の実行ファイルで実行する
1. `dist`フォルダの`pyファイルをまとめてテキスト化(GPT確認用).exe`をPythonファイルが存在するディレクトリに配置します。
2. コマンドプロンプトやバッチファイル、もしくはエクスプローラから直接`.exe`ファイルを実行します。
3. プログラムはカレントディレクトリ内の全ての`.py`ファイルを読み込み、`Pythonファイル内容全文.txt`に保存します。

同梱の`.exe`はバージョン 1.0.0 のままで、下記の更新履歴にある未リリースの変更は含まれていません。引数の指定やUTF-8以外のファイルの読み込みが必要な場合は、Pythonスクリプトを使用してください。

## 文字コードとエラー
- `.py`ファイルの文字コードは、BOMと先頭2行のエンコーディング宣言（`# -*- coding: cp932 -*-`など）から判定し、どちらもなければUTF-8として読み込みます。
- 読み込めないファイルがある場合は、そのファイル名を表示して終了コード1で終了します。このとき出力ファイルは作成・更新されません。宣言のないShift_JIS（cp932）のファイルは`--fallback-encoding cp932`で読み込めます。
- `.py`ファイルが1つもない場合も、出力ファイルを作成・更新せずに終了コード1で終了します。
- 出力ファイルは、すべてのファイルを読み込めた後に置き換えられます。途中で失敗しても、前回の出力ファイルはそのまま残ります。
- 書き込み中は、出力先と同じディレクトリに実行ごとに異なる名前の一時ファイル（`.mergepy-ランダムな文字列.tmp`）を作り、終了時に削除します。既存の`出力ファイル名.tmp`などのファイルには触れません。
- macOS・Linuxでは、新しく作られる出力ファイルは所有者だけが読み書きできる権限（0600）になります。既にある出力ファイルを上書きする場合は、そのファイルの権限を引き継ぎます。
- 内容に「```」を含むファイルは、内容の途中で区切りが閉じないように、より長い区切り（「````」など）で囲まれます。

## 注意点
- 対象ディレクトリ直下の`.py`ファイルのみを扱います。拡張子が大文字の`.PY`ファイルは対象になりません。
- 出力ファイルと同じ名前のファイルが既にある場合は上書きされます。
- 出力ファイルの改行コードは実行したOSの標準（Windowsでは CRLF）になります。
- セキュリティソフトウェアによっては、未知の`.exe`ファイルを実行することに危険性を指摘される可能性があります。信頼性を確認した上で実行を行ってください。

## Pythonから呼び出す
`main.py`をimportしただけでは何も実行されません。バージョン 1.0.0 と同じ`create_combined_python_file(output_filename)`を呼ぶと、カレントディレクトリ直下の`.py`ファイルをまとめ、渡した`output_filename`を返します。

バージョン 1.0.0 と異なり、`.py`ファイルが1つもない場合は空のファイルを作らずに`NoSourceFilesError`を、読み込めないファイルがある場合は`SourceDecodeError`を送出します。

## 開発と検証
テストとlintにはPython 3.10以上と、`requirements-dev.txt`のパッケージを使用します。

```
python -m pip install -r requirements-dev.txt
python -m ruff check .
python -m ruff format --check .
python -m pytest
```

GitHub Actions（`.github/workflows/ci.yml`）でも、WindowsとUbuntuで同じコマンドを実行します。
